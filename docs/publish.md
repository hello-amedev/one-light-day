# 公開の手順

公開の操作は、あめさんの確認を取ってから行う。この文書の手順は、確認が取れるまで実行しない。
準備として、公開用のワークフロー(`.github/workflows/deploy.yml`)は置いてあるが、手動でしか動かない作りで、リポジトリが非公開のいまは動かせない。

## 決めること

| 決めること | 内容 |
|---|---|
| サイト名とリポジトリ名 | 公開の URL は `https://ame-dev.com/<リポジトリ名>/`。リポジトリ名がそのまま URL の末尾になる(例: `one-light-day`)。いまは `voyager` |
| 公開の日 | 未定。候補は、太陽から測って 1 光日になる 2027 年 2 月 4 日ごろ |

## 公開すると起きること

- リポジトリが非公開から公開に変わる。**コードとコミットの履歴が、誰でも見られる状態になる**
- GitHub の無料プランで公開サイトにできるのは、公開リポジトリだけ。サイトだけ公開して中身を隠すことはできない
- いちど公開すると、見られた履歴は取り消せない(あとで非公開に戻しても、見られた事実は消えない)

## 公開の前に確かめること

1. コミットの履歴に、本名や非公開のメールアドレスが無い(作者名と、GitHub の noreply のアドレスだけになっている)。`git log --format='%an %ae' | sort -u` で見る
2. ファイルの中に、パスワード・キー・業務の資料が無い
3. `.env` の `VITE_SITE_URL` が、公開の URL(`https://ame-dev.com/<リポジトリ名>/`)になっている(共有の画像のリンクに使う)
4. 画面の文言の一覧を、あめさんが読んで OK を出している
5. スマホの実機で、開いて、操作して、文字が読めること
6. 出典のページの内容(`THIRD-PARTY-NOTICES.md` と同じ)が最新。天の川の素材は、広告・物販を付けない間だけ使える
7. `npm run verify` が通る

## 手順

1. あめさんが、サイト名・リポジトリ名・公開の日を決める
2. GitHub のリポジトリの設定(Settings → General)で、リポジトリ名を変える。ローカルの接続先も `git remote set-url origin ...` で合わせる
3. 同じ画面の一番下(Danger Zone)で、「Change visibility」から公開に切り替える
4. Settings → Pages で、Source を「GitHub Actions」にする
5. Actions のタブから「Deploy to GitHub Pages」を選び、「Run workflow」で手動で実行する。実行の中身は、依存を入れる → `npm run verify` → `dist/` を公開、の順
6. 実行が終わったら、`https://ame-dev.com/<リポジトリ名>/` を PC とスマホで開いて、表示と操作を確かめる(カスタムドメインの設定は、ame-dev.com のサイトのリポジトリ側で済んでいること)

## 公開のあと

- 更新したい時は、変更を `main` に入れてから、5 のワークフローをもういちど手動で実行する(push では自動で公開されない)
- 問題があって取り下げたい時は、Settings → Pages で公開を止める
